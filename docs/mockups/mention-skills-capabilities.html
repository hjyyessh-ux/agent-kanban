왜 이렇게 나누나

  • 첫 줄 slash → 확장·실행. E2a E3e egm
  • 첫 줄 뒤 본문 전체(참조 블록 포함)가 $ARGUMENTS로 들어갑니다. E2h
  • 본문 중간 slash는 신뢰 불가: 1/4만 성공했습니다. slash-only 스킬은 모델의 스킬 목록에서 숨겨지기 때문입니다. E4d
  • 두 번째 slash-only를 블록에 넣으면 → 거부됩니다. E3a
  • 그래서 UI가 "실행 1개"를 구조적으로 강제합니다 (런처 바는 슬롯 1개).
  • MENTION_TOKEN_RE는 :를 허용하지 않으므로, plugin 스킬 토큰은 런처 바(본문 밖)로 빼는 편이 깔끔합니다.

④ 스킬을 고른 뒤 디렉토리를 바꾸면 쓸 수 없는 스킬을 빨간 칩으로 바꾸고 생성을 막습니다. 실측 E2f: 없는 스킬을 slash로 보내면 오류 없이 평문으로 전달되어 모델이 임의로 수행했습니다 — 조용한 실패이므로 서버 재검증이 필수입니다.

Claude vs Codex

  • 호출 문법: Claude /name 첫 줄 1개 · Codex $name 어디든 여러 개. C6 3/3 C7

스킬 작성자 가이드
claude 카드에서 쓰려면
.claude/skills/<name>/SKILL.md에 둡니다. 사용자가 고를 때만 실행되게 하려면 frontmatter에 disable-model-invocation: true를 넣습니다. 이 경우 칸반에서는 ▶ 실행 바(1개)로만 쓸 수 있습니다.
codex 카드에서 쓰려면
.codex/skills/ 또는 .agents/skills/에 둡니다. 사용자만 호출하게 하려면 agents/openai.yaml에 policy.allow_implicit_invocation: false를 넣습니다. Claude의 frontmatter 플래그는 codex가 무시합니다.
양쪽에서 쓰려면
두 위치에 모두 있어야 합니다 (mcp-server의 zepetoful-daily-health가 이 형태). 한쪽을 symlink로 두는 방식은 실측하지 않았습니다. "사용자만 호출" 설정도 두 파일에 각각 해야 합니다.
주의
  • 런타임을 바꾸면 고른 스킬이 무효가 될 수 있습니다. 칸반이 경고하고 생성을 막습니다 (④와 동일).
  • codex 카드에 /name을 쓰지 마세요. 주입되지 않고 모델이 파일을 찾아 읽는 우회 동작을 합니다 (C9).
  • claude 카드에서 실행 전용 스킬을 본문 중간에 slash로 쓰지 마세요. 4번 중 1번만 실행됐습니다 (E4d).
  • 없는 스킬은 두 런타임 모두 조용히 실패하거나 오실행합니다. 칸반이 제출 직전에 재검증하는 이유입니다 (E2f · C10).
