좌: project 없음 + 예약 Work (상단 좌측이 비어 ☆ #id 만 우측에 남음). 우: project 있음 + Work 없음 (Work 없음 ▾ 가 별도 행으로 붙음).

옵션 A

상단 컨텍스트 슬롯 — W Work › project breadcrumb

상단 좌측 "컨텍스트 슬롯"에 Work → project 순서로 이어 붙입니다. Work 행은 삭제. 둘 다 없어도 ＋ Work 가 자리를 채워 빈칸이 사라집니다. 폭이 모자라면 project 가 먼저 줄어듭니다(Work 우선).

장점

  • 허전함(빈 spacer)과 "아래 붙음" 두 문제를 한 슬롯으로 동시 해결
  • 카드 높이 1행 감소, 높이 일관
  • "어느 Work › 어느 repo" 위계가 한눈에 읽힘

단점

  • 상단 한 줄에 Work + project + ☆ + #id 가 모여 300px 에서 가장 빡빡
  • 예약 + project 동시일 때 Work 라벨이 짧게 잘림
  • project chip 위치가 "맨 왼쪽"에서 두 번째로 이동 (기존 학습 습관 변화)
옵션 B

meta row 병합 — runtime · time ··· Work

Work pill 을 meta row 우측으로 올려 한 행을 줄입니다. project 가 없으면 상단 행 자체를 없애고 ☆ #id 를 제목 줄 우측으로 옮깁니다. 빈 Work 는 hover 시에만 ＋ Work 가 나타납니다(자리는 상시 확보).

장점

  • 가장 낮은 카드 (project 없으면 3행)
  • 빈 Work 는 시각 노이즈 0 — 보드가 깔끔
  • 상단 project chip 위치/모양 그대로 유지

단점

  • project 유무로 카드 높이가 ±24px 달라져 컬럼 리듬이 들쭉날쭉
  • hover-only 라 Work 미배정 카드가 "할당 가능"함을 알리기 어려움 (터치 기기는 .55 상시 노출로 대체)
  • Work 가 meta 우측에 있어 위계상 부차적으로 보임
옵션 C추천

Work 머리띠 — 상단 = Work, project = meta row

상단 좌측을 Work 전용 슬롯으로 씁니다. Work 가 항상(없으면 조용한 ＋ Work) 존재하므로 상단이 비는 일이 구조적으로 없습니다. project 는 meta row 의 runtime · project · time 으로 내려, 없으면 그냥 항목이 하나 빠질 뿐 빈칸이 생기지 않습니다.

장점

  • "빈칸" 문제가 구조적으로 해소 — 비어 보일 슬롯이 없음 (Work 는 항상 존재, project 는 선택 항목)
  • Work 가 제목 바로 위로 올라와 "묶음 소속"이 가장 강하게 읽힘
  • 300px 에서도 줄당 항목이 2~3개로 분산되어 가장 안정적
  • 카드 높이 고정 (4행), 행 하나 감소

단점

  • project chip 이 좌상단에서 meta row 로 이동 → 기존 색상 chip 의 스캔성이 약간 감소
  • Work 미배정 카드에도 상단에 ＋ Work 가 상시 보임 (조용한 톤으로 완화)
  • 상단/meta 두 곳을 재배치하므로 변경 범위가 A 보다 약간 큼

최종 추천: 옵션 C

사용자 불만의 두 축(Work 가 아래 붙음 / project 없을 때 빈칸)을 가장 적은 트레이드오프로 해결합니다. A 는 같은 효과지만 300px 에서 상단이 과밀하고, B 는 카드 높이가 들쭉날쭉하며 빈 Work 가 발견되기 어렵습니다. C 는 높이가 고정이고 300px 에서도 줄 단위로 여유가 있어 ellipsis 로 안전하게 수렴합니다. project chip 위치가 바뀌는 점만 감수하면 되며, 필요하면 A 의 breadcrumb 아이디어를 넓은 폭(380px+)에서만 적용하는 하이브리드도 가능합니다.
