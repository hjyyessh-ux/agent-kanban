다른 열의 상태는 “진행중 세션 1개로 이동”처럼 대상과 단위를 명시합니다.

Timeline 제안

현재 일 단위·디렉토리 → Work → 세션 구조, 날짜 키보드 조정, 네이티브 가로 스크롤은 유지합니다. Work 바는 계획, 보라 레일은 세션 실행 범위라는 짧은 인라인 범례를 도입하고, 카드가 여러 개인 날짜 버튼에 세션명·날짜·상태별 개수를 접근성 이름으로 제공합니다. 이 목업의 일정 strip은 탐색만 시연하며 날짜 드래그는 구현하지 않습니다.

03우선순위와 근거

관찰과 제안을 구분했습니다. 기존에 있는 기능은 발견성을 개선합니다.

P0 의미·접근성 → P1 정보 구조 → P2 효율

스크린샷 파일 자체는 제공되지 않아 상세 Before는 설명과 실제 JSX/CSS를 대조해 재현했습니다. Works Before는 현재 소스의 타임라인 strip, 높이 제한 Inbox, 필터와 Work 행을 반영한 축약 재현입니다. 개선안의 숫자·요약·시간은 샘플이며 실제 저장이나 API 호출은 없습니다.

P0 01 · 의미의 정확성

검토 대기를 “완료”에 합치면 판단이 틀립니다.

관찰 상세의 “완료”는 complete + done, “진행”은 todo + in_progress입니다. 예: 검토 대기 4장도 완료 25장에 포함될 수 있습니다.

제안 4상태를 분리하고, “카드 완료”와 “Work 목표 달성”을 구분합니다. 25/25는 카드 현황이며 Work의 자동 완료나 목표 진척률 100%가 아닙니다.

근거: WorkDetailDialog.tsx 작업 현황 · src/core/timeline-aggregate.ts 집계. 정확한 4상태는 기존 completion-preview의 byStatus 재사용 또는 sessions DTO 확장이 필요합니다. 목록의 혼합 집계로 4분포를 추정하지 않습니다.

P0 02 · 키보드

모달의 포커스 트랩 계약을 먼저 복구합니다.

확인 DialogSkeleton은 모든 keydown 전파를 멈추지만, useModalAccessibility는 window의 bubble 단계에서 Tab을 처리합니다. 마지막 요소의 Tab이 트랩에 도달하지 않습니다.

제안 공통 셸에서 이벤트 처리 위치를 정리하고 중첩 확인창의 최상위 트랩·닫기 후 포커스 복원을 검증합니다. 메뉴·피커를 닫는 Esc가 부모 상세까지 닫지 않아야 합니다.

근거: Card/DialogSkeleton.tsx · hooks/useModalAccessibility.ts · MoveSessionDialog.tsx 주석. 목업은 native dialog.showModal()로 배경 비활성·초기 포커스·Tab·Esc·복귀를 시연합니다. 앱 공통 셸 수정은 별도 범위입니다.

P0 03 · 작업 종료

자주 보는 푸터에서 파괴적 액션을 낮춥니다.

관찰 삭제의 분홍 채움과 초록 완료가 큰 색 면적으로 경쟁합니다. 병합·폐기도 한 레일에 나란합니다. 완료는 이미 확인창과 실행 중 가드가 있습니다.

제안 식별 가능한 “관리” 안에 병합·폐기·삭제를 두고, 푸터에는 “Work 완료…”를 남깁니다. 확인창에서 실제 보관 대상·즐겨찾기 제외·진행 중 차단·오류를 표시합니다.

근거: WorkDetailDialog.tsx 푸터 · WorkResolveConfirmDialog.tsx. 완료 후 재개는 기존 기능입니다. 보관 카드는 done으로 복원되고 에이전트는 실행되지 않습니다. 현재 describeWorkCompletion()의 복원 안내를 유지합니다. 문서 일부의 과거 “되돌릴 수 없음” 서술을 실제 동작으로 오해하지 않습니다.

P1 04 · 상세 위계 / A·B

읽기 화면을 설정 폼처럼 보이게 하지 않습니다.

관찰 전체 폭 Directory와 3개 날짜 타일이 Summary·세션보다 앞입니다. 읽기 전용 최근 활동도 날짜 입력과 같은 외관입니다. 빈 요약과 추가할 세션 0개도 큰 영역을 차지합니다.

제안 프로젝트·최근 활동은 메타 한 줄, 일정은 disclosure, 빈 Summary는 한 문장, 세션 연결은 요청 시 열기. 변경 가능한 제목에는 항상 작은 편집 표시를 둡니다.

근거: Works.css의 .work-meta-card min-height 76px · .work-detail-overview 48px gutter. 제목 인라인 편집·메모 보호는 이미 있으므로 유지합니다.

P1 05 · 목록 / C·D

Work를 찾기 전에 triage를 지나가게 하지 않습니다.

관찰 타임라인·Inbox가 목록 앞에 직렬로 놓입니다. Inbox에는 여러 추천, 새 Work, combobox가 반복됩니다. 기존 검색·필터·정렬·배치 배정은 이미 갖춰져 있습니다.

제안 넓은 화면은 목록 + Inbox, 작은 화면은 목록 뒤 Inbox. 일정 strip은 접어서 시작합니다. 계보 추천은 “연결” 동사로, 디렉토리 일치는 선택지로 표시합니다. 검색 범위를 각 영역에 명시합니다.

근거: WorksView.tsx · InboxSuggestions.tsx · WorkAssignInline.tsx. 기존 BulkAssignModal 순서대로 배정과 기본 역할 변경도 실제 적용 시 계속 제공합니다.

P1 06 · 색·대비

브랜드색은 그대로, 읽을 글자는 semantic 토큰으로.

관찰 검토 대기의 분홍은 삭제와 가깝고, Summary는 내용과 무관하게 초록 성공면입니다. 완료된 Work 행의 opacity: .82는 AA를 보장한 텍스트 토큰까지 흐립니다.

제안 상태는 작은 점·짧은 막대와 텍스트를 함께 사용합니다. 요약은 중립면, 완료 기록은 불투명 텍스트를 유지합니다. 파란 Work 일정 바와 파란 대기 카드는 단위 라벨로 구분합니다.

근거: Works.css의 .works-card-summary · .works-card--resolved. 토큰 원문 전체를 이 페이지에 내장했습니다. 색만으로 전달하지 않으며 대비 검증 수치는 아래에서 현재 테마 기준으로 계산합니다.

P2 07 · 세션 근거

메타를 반복하는 대신 작업 흐름을 보여줍니다.

관찰 5개 세션마다 같은 프로젝트·런타임·ID가 반복되고, 순서와 역할은 읽어야 알 수 있습니다. 세션 행 클릭과 키보드 Enter/Space는 이미 지원됩니다.

제안 같은 프로젝트는 상단에서 한 번, 각 행은 역할·시각·카드 수로 압축합니다. 다른 디렉토리는 행에 꼭 표시합니다. 목록/활동 전환으로 리뷰 → 수정 흐름을 보며 대화로 들어갑니다.

근거: WorkDetailDialog.tsx sessionRows · WorkSessionMenu.tsx. 역할·이동·연결 해제는 메뉴에 유지합니다. 목업 활동은 세션 시각 기반이며 이벤트 감사 로그를 발명하지 않습니다.

P2 08 · 빈 값·오류

0개, 모름, 오래됨을 다른 상태로 보여줍니다.

관찰 상세는 조회 실패 경고가 있지만 보드 카드 폴백 집계가 함께 나타납니다. archive된 카드가 빠진 폴백이면 실제보다 작은 숫자를 볼 수 있습니다.

제안 첫 로딩은 skeleton, 실패는 “집계 확인 불가” 또는 마지막 확인값·시각, 검색 0건은 필터 해제, 빈 Work는 세션 연결, 빈 Inbox는 정리 완료 + 폐기 세션 복원 경로를 제공합니다.

근거: WorkDetailDialog.tsx detail 폴백 · WorkSessionPicker.tsx · WorksView.tsx empty. 상세 상태 선택과 목록 검색, Inbox 폐기 목록으로 체험할 수 있습니다.

P2 09 · 공간·단위

Timeline과 Board의 “부분”을 전체로 오해하지 않게.

관찰 Board의 같은 Work는 여러 상태 열로 나뉩니다. Work → 세션 → 카드의 중첩 상자, 양쪽 접기 버튼, 다른 열 링크가 동시에 나타납니다. Timeline은 계획·실행 범위·카드 상태를 한 그리드에 담습니다.

제안 “현재 열 2 / 전체 5 세션”처럼 범위를 명시하고 헤더 접기를 일관되게 둡니다. Timeline은 계획/실행 의미를 짧게 남기고, 날짜 버튼에 세션명·날짜·상태 개수를 읽어줍니다.

근거: BoardWorkContainer.tsx · TimelineView.tsx SessionRailView. 카드 여러 장인 .tl-day는 시각적 제목은 첫 카드 하나만 보여주므로 title 외 명시적인 접근성 이름 보강을 권합니다. 기존 키보드 날짜 편집은 유지합니다.
