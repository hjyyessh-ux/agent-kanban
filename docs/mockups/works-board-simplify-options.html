A. 껍데기 걷어내기 — 구조는 그대로, 장식·중복만 제거

Work 상자 안에 세션 카드가 들어가는 3겹 구조는 유지합니다. 대신 WORK/SESSION 탭, ID, 중복 칩(W 칩·태그), 큰 버튼 줄, 정렬 토글을 걷어내고 턴 박스를 점·선 타임라인의 2줄 항목으로 가볍게 만듭니다. 기존 코드에서 가장 적게 바뀝니다.

HOVER / ⋯ 열림 상태
첫 사용자 혼란 해소: 탭 라벨 2개와 ID 3개, 같은 정보를 반복하는 W 칩·태그가 사라져 "무엇이 상자이고 무엇이 내용인가"가 한눈에 읽힙니다. 버튼은 ⏎ · ✓ 완료 · ⋯ 한 줄로 합쳐져 "HIDE 와 완료가 왜 양 끝에 있지?" 질문이 없어집니다. 다만 깊이(3겹)와 "Work > 세션" 개념 자체의 낯섦은 그대로입니다.
구성남긴 것줄인 것옮긴 곳

  • 변경 범위 최소 — 기존 컴포넌트에서 CSS와 조건부 렌더링 위주
  • 기존 사용자(소유자)의 멘탈 모델이 그대로 유지됨
  • 모든 액션이 눈에 보여 발견성이 높음

단점

  • "상자 속 상자" 3겹이 남아 첫인상 복잡도가 가장 크게 남음
  • 세션이 늘면 높이가 많이 길어짐(세션당 약 250px)
  • 상시 버튼이 여전히 2개(⏎, ✓)라 카드 수만큼 반복됨

B. Work는 섹션 헤더, 세션은 카드 — 깊이를 3겹에서 2겹으로

Work를 상자가 아닌 "섹션 제목 + 파란 밑줄 + 왼쪽 레일"로 바꿔 세션 카드와 같은 평면에 둡니다. 세션 카드는 최근 2턴만 미리보기로 보여주고 나머지는 "이전 N턴 ›"으로 세션 모달에 넘깁니다. 세션 액션은 hover 시 카드 오른쪽 위에 나타나고, 가장 중요한 Work 완료만 헤더에 상시 노출됩니다.

HOVER 상태 (Work 헤더 + 세션 카드)
첫 사용자 혼란 해소: "Work = 제목이 붙은 묶음, 세션 = 그 아래 카드"라는 문서 목차 같은 구조라 설명이 필요 없습니다. 상자가 하나 사라져 깊이 혼란이 해결되고, 카드마다 반복되던 버튼이 hover로 들어가며 "이 화면에서 누를 수 있는 것"이 Work 완료 하나로 정리됩니다. "Work 없음" 구역이 Inbox 개념을 같은 언어로 보여줍니다.
구성남긴 것줄인 것옮긴 곳
Work이름, 세션 수, unread, ✓ Work 완료(상시)상자·탭·태그 칩·ID·겹친 그림자헤더 hover ⋯에 이름 변경 / ID 복사 / 폐기. 드래그 배정은 레일 + 헤더 전체가 드롭 대상(드롭 시 레일 파란 강조)
세션 카드제목, 디렉토리 칩, 턴 수, 최신 시각, unread, 상태색 띠SESSION 탭, ID, runtime 알약, W 칩, 정렬 토글, HIDE/완료 버튼 줄⏎ resume · ✓ 세션 완료 · ⋯(숨기기·Work 변경·정렬·ID)는 hover 시 메타 줄 오른쪽에 표시
타임라인최근 2턴 질문→답, unread 링, ★ 상시3턴 → 2턴, 박스, NEW/LATEST 배지나머지는 "이전 N턴 ›" → 세션 모달. 즐겨찾기 ☆는 턴 행 hover

장점

  • 깊이가 2겹으로 줄어 개념이 가장 직관적
  • 최근 턴 미리보기는 살아 있어 "정보를 너무 뺐다"는 반론이 없음
  • Work 완료가 헤더 한 곳에 모여 일괄 archive 의미가 분명

단점

  • Work 컨테이너 제거로 드래그 드롭 대상·강조 CSS를 새로 설계해야 함
  • hover 액션은 터치/키보드에서 :focus-within 대응 필요
  • 세션당 약 190px — A보다 낮지만 C보다 큼

C. 접었다 펼치기 — 평소엔 최신 턴 1줄, 클릭하면 인라인 타임라인

세션은 기본적으로 접힌 2~3줄 행(제목 · 최신 질문→답 한 줄 · 메타)이고, 행을 클릭하면 그 자리에서 최근 4턴 타임라인이 펼쳐집니다(아코디언: 한 번에 한 세션). 직전 "너무 접은" 제안과 달라지는 점은 타임라인이 사라지지 않고 한 번 클릭 거리에 있고, 펼친 상태가 보드에서 유지된다는 것입니다. 왼쪽 컬럼에서 직접 클릭해 보세요.

펼침 + HOVER 상태 (정적 캡처)
첫 사용자 혼란 해소: 첫 화면의 정보량이 "제목 + 한 줄"로 가장 적어 "어디를 봐야 하지?"가 사라집니다. 깊이 혼란은 접힘 상태에서 거의 없고, 필요한 사람만 펼쳐서 타임라인을 봅니다. 다만 "왜 어떤 건 접혀 있고 어떤 건 열려 있지?"라는 새 질문이 생기므로 ▸ 아이콘과 클릭 가능한 커서·hover 배경이 필수입니다.

  • "최신 턴 한 줄"만으로도 대부분의 확인 용무가 끝남

1. 소유자 피드백에 가장 정확히 맞습니다. "유용한 정보(최근 턴·unread·상태·완료)는 남기고 노이즈와 깊이만 줄여라"를 그대로 구현합니다. 타임라인이 보드에 남아 직전 제안의 "과도한 단순화"를 반복하지 않습니다.
2. 첫 사용자 문제의 뿌리(3겹 + 상시 버튼)를 둘 다 해결합니다. A는 깊이를, C는 정보량을 건드리지만 B만 둘을 함께 줄이면서 새 규칙(펼침 상태)을 만들지 않습니다.
3. 구현 위험이 관리 가능합니다. 가장 까다로운 부분은 Work 컨테이너가 사라지면서 생기는 드래그 드롭 대상 처리뿐이며, .kv2-work 대신 레일 + 헤더를 드롭 영역으로 쓰면 됩니다.
단계 제안: ① 먼저 A의 "껍데기 걷기"(탭·ID·W 칩·정렬 토글 제거, 버튼 ⋯ 통합)를 공통 선행 작업으로 적용 → ② Work 상자를 헤더+레일로 교체(B) → ③ 반응이 좋으면 "세션 행 접기" 토글만 선택 기능으로 추가(C의 일부). A 작업은 B·C 모두의 전제라 버려지지 않습니다.

공통 유지 사항: 카드 상태색(--kv2-status-*)은 왼쪽 띠·타임라인 점에만 사용, Work는 블루(--kv2-work-*)만 사용. Work 완료 = 일괄 archive, 드래그 Work 배정, resume 복사, 세션 숨기기, 즐겨찾기 ☆, unread는 모두 위치만 옮기고 삭제하지 않았습니다. 높이 수치는 이 목업 렌더링 기준 추정치입니다.
