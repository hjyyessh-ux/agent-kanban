점검 결과 — 구체적 문제 12개

  1. 색섹션 바가 다크 토큰이 아니라 라이트용 포화색을 직접 씁니다 .kv2-list-section-header[data-status]가 --kv2-status-*-bg(#ff3b6b / #facc15 / #22c55e / #1e66f5)를 그대로 씁니다. 다크 테마가 덮어쓰는 건 --kv2-column-header-*-bg(20~24% 혼합)뿐인데 보드만 이쪽을 쓰고 리스트는 안 씁니다. 상대 휘도 0.64/0.41/0.25/0.16 짜리 면이 휘도 0.012 배경 위에 전폭으로 깔려 눈부심의 원인입니다.
  2. 색모든 행에 같은 분홍→노랑 그라데이션 띠가 붙습니다 .kv2-list-table-row::before가 --kv2-list-row-accent-from/to(rgba(251,113,133)→rgba(250,204,21)) 고정값입니다. 완료 행에도, 대기 행에도 같은 띠 → 상태와 무관한 장식이 "검토 대기"처럼 읽힙니다.
  3. 밀도행 하나가 ~80px, 행 간격 10px 포함 피치 90px 패딩 13+13, 제목 --kv2-text-lg(line 1.28), 요약 줄(line 1.55), 2px 테두리, 4px 하드 섀도. 900px 화면에 약 8행. 완료 232장을 펼치면 약 2만 px.
  4. 낭비빈 섹션이 100px+ 점선 박스 0건이어도 컬럼 헤더 + .kv2-empty "No cards" 박스가 그대로 나옵니다. 위 재현에서 진행중이 그 경우.
  5. 낭비컬럼 헤더가 섹션마다 4번 반복, 라벨도 거침 mono 대문자 FAV TITLE RUNTIME ACTION QUEUE CREATED. "FAV"는 아이콘 열이고, 행이 0개인 섹션에도 나옵니다.
  6. 낭비QUEUE 열이 폭의 ~16%를 차지하지만 대부분 비어 있음 큐가 걸린 대기 카드에서만 값이 있습니다. 나머지 95% 행에서는 빈 칸.
  7. 일관성시간 표기가 보드와 다릅니다 리스트 2026-11-04 11:00(절대, mono) vs 보드 2h ago / 마지막 hh:mm. 또 "Created"는 검토/완료 단계에서 중요한 값이 아니라 마지막 활동이 중요합니다.
  8. 구조Works / Session이 전혀 반영되지 않습니다 BoardScreen이 worksModel·unreadBySession·navOrder의 groupComplete를 전부 viewMode === 'board'에서만 켭니다 (테스트 "the list view ignores Work containers even in works mode"). 한 세션의 카드 26장이 서로 무관한 26행이 되고 GROUP 토글은 무반응.
  9. 구조프로젝트 정보가 없습니다 행에 project 칩이 없어 agent-kanban / zanything / mcp-server 카드를 구분 못 합니다. 보드 카드는 project가 맨 앞.
  10. 구조완료(232)가 맨 위, 기본 펼침, 접힘 상태 비저장 LIST_ORDER가 done을 처음에 두고 useState 초깃값이 전부 false(펼침)라 새로고침마다 232행이 위를 덮습니다. 손이 필요한 검토 대기가 두 번째.
  11. 색헤더 요소 대비·무게 800 weight 대문자 + 2px 프레임 박스 카운트. 카운트 글자색이 상속된 --kv2-frame(#0e0e15)라 #272a2e 위에서 약 1.3:1. unread dot도 테두리가 --kv2-ink-black(다크에서 #3c4146)이라 하드 섀도와 함께 뭉개집니다. 섹션별 안 읽음 수(column.unreadCount는 있음)는 표시되지 않습니다.
  12. 인터랙션hover가 행을 움직이고, 좁은 폭 대응이 없습니다 .kv2-list-table-row:hover가 translate(-1px,-1px) + 섀도 변경 → "hover는 opacity만" 원칙 위반. ≤768px는 6열 비율만 바꿀 뿐 카드형 전환이 없어 제목이 거의 잘립니다.

  • 스캔성 최고. 모든 행이 같은 그리드라 project·runtime·시간이 세로로 정렬됨.

  • 같은 세션 카드끼리 묶어 처리(일괄 완료 등)하려면 보드로 가야 함.
OPTION B

B · 보드 미러 — Work ▸ Session ▸ turn 박스를 리스트에 이식

상태 섹션 틀은 A와 같고, 검토 대기 안에서 보드와 같은 WORK / SESSION 탭 박스, 세션 N · 총 소요 · 마지막, ● N, ★ N, 댓글형 turn(질문 → ↳ 답)을 그대로 씁니다. 대기/진행중/완료는 평면 행.

장점

  • Work/세션/turn 계층과 요약(안 읽음·★·소요)을 가장 충실히 보여줌. 보드 컴포넌트 재사용 가능.
  • 세션 단위 액션(✓ 완료, resume)과 turn별 즐겨찾기를 바로 사용.
  • 보드와 시각적으로 완전히 같아 학습 비용 0.

단점

  • 크다. 세션 박스 1개 = 150~330px. "사이즈가 너무 크다"는 불만과 정면 충돌, 화면당 3~5 세션.
  • 박스 높이가 제각각이라 위아래 비교/스캔이 어렵고, 리스트가 보드의 세로 복제로 전락.
  • GROUP=CARD일 때의 모습은 별도로 정의 필요(결국 A가 또 필요). drag&drop·unread jump 회귀 범위가 큼.
OPTION C · 추천

C · 하이브리드 — 같은 5열 그리드에 Work 헤더 행 / 세션 행 / turn 행

카드 행은 A와 동일. GROUP 토글이 리스트에서도 동작합니다. CARD = A와 같은 평면, SESSION = 세션 1개가 1행(#id · 세션 26 · ● 5 · ★ 2, 마지막 시각), WORKS = 얇은 Work 헤더 행(WORK 탭 + 2 sessions · 총 소요) 아래 세션 행이 들여쓰기. 세션 행의 ▸를 누르면 turn 행(번호 · 질문 · ↳ 답 한 줄 · 시각 · ★)이 펼쳐집니다. 아래 위젯을 직접 눌러 보세요 (GROUP 전환, 섹션/Work/세션 접기, ★ 토글).

1400px · 데스크톱

장점

  • 불만 3개(색·크기·Works/Session)를 한 번에 해결. 행 높이는 A와 같은 40px.
