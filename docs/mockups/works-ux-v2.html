② 목록의 요약 한 줄이란?

Codex 목업의 "재시도 큐 병목을 확인했습니다. 처리량 변경안을 리뷰할 차례입니다"는 임의로 지어낸 메모가 아닙니다. Work.summary.lines[0], 즉 Work 상세에서 요약 생성을 눌러야 LLM이 만드는 3~5줄 요약의 첫 줄을 예시 값으로 넣은 것입니다. 실제로는 대부분의 Work에 요약이 없어서 빈 줄이 됩니다. 그래서 아래 순서로 채우고, 어디서 온 문장인지 꼬리표를 붙입니다.

④ 검색 결과 UI — Obsidian vs ClickUp

Obsidian 방식 권장 · Work 상세
  • 결과를 문서(=세션) 단위로 묶고 매칭 수를 보여 준 뒤, 펼치면 본문 조각에 하이라이트
  • Work → 세션 → 카드(turn)라는 실제 계층과 맞음. "어느 세션의 몇 번째 turn"인지 바로 보임
  • 조각을 읽고 들어갈지 판단할 수 있음. 세션 모달 하이라이트로 자연스럽게 이어짐
  • 단점: 결과가 많으면 길어짐 → 세션 그룹마다 기본 3줄 + "n개 더"
▾ 재시도 큐 처리량 측정3
T2 · …재시도 큐 consumer가 초당 120건에서…
▸ retry backoff 설정 검토1
ClickUp 방식 나중에 · 전역 검색용
  • 평평한 한 줄 목록 + 종류 아이콘 + 위치("in Tasks (SP)") + 시간. 키보드로 고르고 Enter
  • "이름을 아는 것을 빨리 찾아 여는" 데 강함 → 앱 전체 빠른 이동(⌘K)에 적합
  • 본문 조각이 없어 "어떤 내용이 걸렸는지"를 알 수 없음 → 한 Work 안에서 내용을 찾을 때는 약함
  • 단축키를 안 쓰신다고 해서 지금은 우선순위가 낮음
◉ [ingestion] 재시도 큐 처리량 측정 in Work · 6d
◉ [mcp-server] retry backoff 설정 검토 in Work · 2d

결론: Work 상세 안 검색은 Obsidian 방식(세션별 묶음 + 조각 하이라이트)으로 하고, 결과 줄 오른쪽에 T# 칩을 달아 말씀하신 "카드 번호를 누르면 하이라이트된 곳으로 이동"도 함께 넣었습니다. ClickUp 방식은 Works·Board 전체를 가로지르는 전역 검색을 만들 때 다시 검토하면 됩니다.

⑤ 구현 메모 · 날짜 하한 체크 결과

날짜 하한(최초 Work 시작일 이전으로 스크롤 금지): 지금은 없습니다. timelineModel.ts의 bufferEdgeToExtend는 화면이 왼쪽 끝 7일 안에 들어오면 무조건 'start'를 돌려주고, extendBuffer는 하한 없이 28일씩 과거를 붙입니다. 그래서 Works 탭 strip과 Board 타임라인 모두 끝없이 왼쪽으로 갑니다. 구현할 때 넣겠습니다.

변경내용
날짜 하한 earliestTimelineView에 earliest?: Date를 추가합니다. bufferEdgeToExtend/extendBuffer는 buffer.start ≤ earliest이면 과거로 늘리지 않고, ◀ 7일은 그 지점에서 비활성 + 안내를 띄웁니다. strip은 진행 중 Work들의 min(startedAt), Work 상세는 그 Work의 startedAt을 씁니다. Board 전체 타임라인은 지금처럼 하한 없음(옵션).
세션 흐름 = TimelineView 재사용새 variant="work"(또는 workId prop): 그 Work의 바 1줄 + sessionLinks의 세션 행만, 항상 펼친 상태로 보여 줍니다. 미배정·다른 Work·프로젝트 그룹 행은 렌더하지 않습니다. 세션 행 라벨에 프로젝트 칩을 붙입니다(여러 프로젝트가 섞이므로). 데이터는 기존 GET /api/timeline 응답을 그 세션 ID들로 거르기만 합니다.
목록 정렬 "실행 중 먼저"Work에 연결된 세션 중 in_progress 카드가 있으면 상단 그룹으로 올립니다. 보드 카드로 계산할 수 있어 API 변경은 없습니다.
다중 프로젝트 칩sessionLinks[].projectDir를 세어 개수가 많은 순서로 나열합니다. 기존 dirAccentClass 색을 그대로 씁니다.
요약 한 줄 대체 순서요약 → 메모 → 최근 결과(previewLine) → 빈 상태(②).
미배정 숨김미배정 개수가 0이면 섹션 자체를 렌더하지 않습니다. 폐기 세션 복원 진입점은 Works 헤더의 ⋯로 옮깁니다.
세션 검색보드에 있는 카드 + 보관된 카드에서 제목·프롬프트·결과를 클라이언트에서 검색합니다(보관 카드는 상세를 열 때 한 번 조회). 결과를 누르면 SessionConversationModal에 초기 검색어와 turn을 넘깁니다(prop 추가).
