# 스케줄러

## 개요

스케줄러는 cron 표현식을 사용해 반복 자동화 작업을 설정할 수 있는 기능이다. 작업은 두 가지 유형으로 나뉜다. 쉘 명령(shell)은 `Bun.spawn()`으로 직접 실행되며 LLM 토큰을 소비하지 않는다. opencode 스킬 실행(skill)은 AI 에이전트를 호출하므로 토큰을 소비한다.

스케줄러 데이터는 기본적으로 `~/.agent-kanban/schedulers.json`에 저장된다. `KANBAN_DATA_DIR`을 설정한 경우 해당 경로가 우선한다. 칸반 보드와 동일한 원자적 쓰기(atomic write) 및 이중 잠금(dual locking) 방식으로 데이터 무결성을 보장한다. 스케줄러 엔진은 `croner` 라이브러리(v10.0.1)를 사용하며, 플러그인 생명주기에 따라 `start()`와 `stop()`이 관리된다.

## 스케줄러 항목 구조

각 스케줄러 항목(`SchedulerEntry`)은 다음 필드로 구성된다.

| 필드 | 타입 | 필수 여부 | 설명 |
|------|------|-----------|------|
| `id` | `string` | 필수 | UUID, 자동 생성 |
| `name` | `string` | 필수 | 스케줄러 이름 |
| `description` | `string` | 필수 | 스케줄러 설명 |
| `cron` | `string` | 필수 | 5-field cron 표현식 (분 시 일 월 요일) |
| `cronDescription` | `string` | 선택 | cron 표현식의 사람이 읽기 쉬운 설명 |
| `timezone` | `string` | 선택 | 타임존 (예: `"Asia/Seoul"`, `"UTC"`) |
| `status` | `'active' \| 'inactive'` | 필수 | 활성(active) 또는 비활성(inactive) 상태 |
| `action` | `SchedulerAction` | 필수 | 실행할 작업 (아래 참조) |
| `lastRunAt` | `string` | 선택 | 마지막 실행 시각 (ISO 8601) |
| `nextRunAt` | `string` | 선택 | 다음 실행 예정 시각 (ISO 8601) |
| `lastRunStatus` | `'success' \| 'failure'` | 선택 | 마지막 실행 결과 |
| `history` | `SchedulerRun[]` | 필수 | 실행 이력 목록 |
| `createdAt` | `string` | 필수 | 생성 시각 (ISO 8601) |
| `updatedAt` | `string` | 필수 | 마지막 수정 시각 (ISO 8601) |

### action 필드 상세

`action` 필드는 실행할 작업의 유형과 세부 내용을 담는다.

**shell 타입**

```json
{
  "type": "shell",
  "command": "echo hello"
}
```

| 필드 | 타입 | 설명 |
|------|------|------|
| `type` | `'shell'` | 쉘 명령 실행 |
| `command` | `string` | 실행할 쉘 명령어 |

**skill 타입**

```json
{
  "type": "skill",
  "skillName": "example_skill",
  "skillInput": "칸반 보드 현황을 Slack으로 전송"
}
```

| 필드 | 타입 | 설명 |
|------|------|------|
| `type` | `'skill'` | opencode 스킬 실행 |
| `skillName` | `string` | 실행할 스킬 이름 |
| `skillInput` | `string` | 스킬에 전달할 입력값 |

## SchedulerRun 구조

각 실행 기록(`SchedulerRun`)은 다음 필드로 구성된다.

| 필드 | 타입 | 필수 여부 | 설명 |
|------|------|-----------|------|
| `id` | `string` | 필수 | 실행 ID (UUID) |
| `startedAt` | `string` | 필수 | 실행 시작 시각 (ISO 8601) |
| `completedAt` | `string` | 선택 | 실행 완료 시각 (ISO 8601) |
| `status` | `'success' \| 'failure' \| 'running'` | 필수 | 실행 상태 |
| `output` | `string` | 선택 | 표준 출력(stdout) 내용 |
| `error` | `string` | 선택 | 표준 오류(stderr) 또는 에러 메시지 |
| `exitCode` | `number` | 선택 | 프로세스 종료 코드 |
| `triggeredBy` | `'cron' \| 'manual'` | 필수 | 트리거 방식 (cron 자동 실행 또는 수동 실행) |

## 자연어 cron 파싱

스케줄러는 한국어와 영어 자연어 입력을 cron 표현식으로 자동 변환하는 기능을 제공한다. 별도의 cron 문법을 외우지 않아도 직관적인 문장으로 스케줄을 설정할 수 있다.

### 변환 예시

**한국어 입력**

| 자연어 입력 | 변환된 cron 표현식 | 의미 |
|-------------|-------------------|------|
| `매 5분마다` | `*/5 * * * *` | 5분마다 |
| `매일 오전 9시` | `0 9 * * *` | 매일 09:00 |
| `매주 월요일 오후 2시` | `0 14 * * 1` | 매주 월요일 14:00 |
| `매시간` | `0 * * * *` | 매 정각 |
| `매일 자정` | `0 0 * * *` | 매일 00:00 |

**영어 입력**

| 자연어 입력 | 변환된 cron 표현식 | 의미 |
|-------------|-------------------|------|
| `every hour` | `0 * * * *` | 매 정각 |
| `every weekday at 9am` | `0 9 * * 1-5` | 평일 09:00 |
| `every 5 minutes` | `*/5 * * * *` | 5분마다 |
| `every day at midnight` | `0 0 * * *` | 매일 00:00 |

### 파싱 실패 시

자연어 파싱이 실패한 경우, 표준 5-field cron 표현식을 직접 입력해야 한다. cron 표현식 형식은 아래 섹션을 참고한다.

---

## Cron 표현식 형식

cron 표현식은 5개의 필드로 구성되며, 각 필드는 공백으로 구분된다.

```
분 시 일 월 요일
```

| 필드 | 허용 범위 | 설명 |
|------|-----------|------|
| 분 | 0-59 | 실행할 분 |
| 시 | 0-23 | 실행할 시각 |
| 일 | 1-31 | 실행할 날짜 |
| 월 | 1-12 | 실행할 월 |
| 요일 | 0-6 | 실행할 요일 (0=일요일, 1=월요일, ..., 6=토요일) |

### 특수 문자

| 문자 | 의미 | 예시 |
|------|------|------|
| `*` | 모든 값 | `* * * * *` = 매 분마다 |
| `*/N` | N 간격 | `*/15 * * * *` = 15분마다 |
| `,` | 목록 | `0 9,18 * * *` = 09:00과 18:00 |
| `-` | 범위 | `0 9 * * 1-5` = 평일 09:00 |

### 자주 쓰는 표현식 예시

| cron 표현식 | 실행 주기 |
|-------------|-----------|
| `* * * * *` | 매 분마다 |
| `*/5 * * * *` | 5분마다 |
| `0 * * * *` | 매 정각 |
| `0 9 * * *` | 매일 09:00 |
| `0 9 * * 1-5` | 평일 09:00 |
| `0 9 * * 1` | 매주 월요일 09:00 |
| `0 0 1 * *` | 매월 1일 00:00 |
| `0 0 * * 0` | 매주 일요일 00:00 |

## 액션 유형

### shell

쉘 명령을 `Bun.spawn()`으로 실행한다. 외부 프로세스를 별도로 띄우지 않고 가볍게 동작하며, LLM 토큰을 전혀 소비하지 않는다. 실행 중 표준 출력(stdout)과 표준 오류(stderr)가 모두 캡처되어 실행 이력에 저장된다.

shell 타입이 적합한 경우:
- 파일 백업, 로그 정리 등 시스템 작업
- 외부 스크립트 실행
- 데이터 수집, 알림 전송 등 토큰 소비가 없어야 하는 작업

### skill

opencode 스킬을 호출한다. AI 에이전트가 직접 실행되므로 LLM 토큰을 소비한다. 비용이 발생할 수 있으므로 UI에 경고가 표시된다. 빈번한 스케줄(예: 매 분, 매 5분)에는 신중하게 사용해야 한다.

skill 타입이 적합한 경우:
- AI가 판단하고 응답해야 하는 작업
- 칸반 보드 상태 분석 후 Slack 전송 같은 지능형 자동화
- 정기적인 코드 리뷰나 문서 생성 작업

## 실행 이력

스케줄러가 실행될 때마다 실행 기록이 생성된다. 각 기록에는 시작/완료 시각, 실행 상태, stdout/stderr 출력, 프로세스 종료 코드가 포함된다. 기록은 `schedulers.json` 파일 내 해당 스케줄러 항목에 인라인으로 저장된다.

실행 이력은 UI의 `SchedulerHistoryPanel` 컴포넌트에서 확인할 수 있다. 각 스케줄러 항목마다 최근 N건의 실행 이력이 보존된다.

실행 이력에서 확인할 수 있는 정보:
- 실행 시작 및 완료 시각
- 성공/실패/실행 중 상태
- stdout 출력 내용
- 오류 메시지(있는 경우)
- 프로세스 종료 코드
- cron 자동 실행인지 수동 실행인지 여부

## 활성/비활성 토글

각 스케줄러는 `active`(활성) 또는 `inactive`(비활성) 상태를 가진다.

**활성 상태(active)**
- cron 스케줄에 따라 자동으로 실행된다.
- 스케줄러 엔진이 해당 항목의 cron 표현식을 감시하고 실행을 트리거한다.

**비활성 상태(inactive)**
- 자동 실행이 중단된다.
- 스케줄러 설정(cron, action, description 등)은 그대로 유지된다.
- 언제든지 다시 활성화할 수 있다.

토글은 plugin tool 또는 HTTP API를 통해 수행할 수 있다. 비활성화된 스케줄러도 수동 실행(manual trigger)은 가능하다.
