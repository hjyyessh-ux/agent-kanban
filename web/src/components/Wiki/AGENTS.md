# Wiki

## Purpose
UI for the LLM-generated knowledge base ("wiki") built from completed kanban cards: configuration of the summarization model/route, a force-directed graph of generated docs, a per-card wiki detail dialog, and archive/backfill controls. Child cards are excluded from wiki processing (see git history) — only top-level completed cards get summarized.

## Key Files
| File | Description |
|------|-------------|
| `WikiView.tsx` | Top-level tab container. Fetches wiki status/config/archive via `useWikiApi`, orchestrates reprocessing, backfill runs, and worker restarts, and composes `WikiConfigPanel` + `WikiGraph` + `WikiCardDialog` + `Board/SessionConversationModal` (for viewing the source session behind a doc). Defines the `WikiTile` shape consumed by the graph. |
| `WikiConfigPanel.tsx` | Model/route configuration for the summarization LLM. Lists every Codex/Claude model from the shared runtime catalog, grouped by CLI route, with a custom free-text fallback and `CodexReasoningEffort` selection. |
| `wiki-model-options.ts` | Pure helper that projects the shared runtime catalog into the Codex/Claude model groups supported by the wiki worker. |
| `WikiGraph.tsx` / `WikiGraph.css` | Force-directed visualization (`react-force-graph-2d`) of wiki docs, colored/shaped by `WikiDocType` (troubleshooting/howto/decision/concept/reference) with a live-tunable, localStorage-persisted settings panel for visual/force parameters. |
| `WikiCardDialog.tsx` | Per-card dialog showing the generated wiki doc for a `KanbanCard` (fetched via `fetchWikiDoc`), an Obsidian deep link built from the worker's `vaultDir`, and a manual "reprocess" trigger. |
| `Wiki.css` | `.wiki-*` styling for the view, config panel, and card dialog (graph styling is separate in `WikiGraph.css`). |

## For AI Agents
### Working In This Directory
- The model picker must consume `useRuntimes()`/`src/core/runtime-config.ts`; do not introduce a second hardcoded wiki model list. Persist the selected `route` with the model so Codex models are not identified by naming convention alone.
- `WikiGraph.tsx` persists its visual/force tuning to localStorage — treat the settings shape as a versioned contract; changing field names without a migration will silently reset users' saved graph layouts.
- Wiki docs are read-only summaries generated by an offline worker — this directory never writes doc content directly; it only triggers reprocess/backfill requests and displays results.

### Testing Requirements
- No colocated tests currently. Graph layout/force logic is highly visual and hard to unit test; prefer manual verification (`bun run dev`) for `WikiGraph.tsx` changes.

### Common Patterns
- Markdown rendering reuses `Card/CardMarkdown.tsx` (`WikiCardDialog.tsx`) rather than a separate renderer.
- Status/progress display for long-running backfill or worker-restart operations follows the same poll-until-settled pattern used in `Settings/SettingsMaintenancePanel.tsx`.
